## [Unreleased]

### Added

- Initial release of the emitter. It generates a C# client built on Flurl.Http and mirrors `@massivescale/tsp-refit-client`: the same options, `@clientName` / `@access` decorators, API versioning (`target-version`, `all-versions`, `version-in-namespace`, `route-prefix`), `@discriminator` polymorphism, `@encode("string")` booleans, visibility-filtered request records, merge-patch bodies, Handlebars template overrides, NuGet metadata, and the `internal-access-leak` lint rule.
- One endpoint interface (`IWidgets`) and one internal Flurl-backed implementation (`WidgetsEndpoint`) per TypeSpec interface, an aggregate client with the underlying `IFlurlClient` exposed as `FlurlClient`, `Create` factories for use without dependency injection, and an `Add{Client}` registration method built on `IHttpClientFactory`, so delegating handlers and resilience policies can be added.
- **Extensible models.** Generated records are never sealed, so callers can derive their own types and send them to the API with their extra properties intact.
  - Every operation whose response contains a model gets a generic overload (`ReadAsync<TResult>(...) where TResult : Widget`) that deserializes the response as the caller's derived type. `Widget[]` becomes `List<TResult>` and `Record<Widget>` becomes `Dictionary<string, TResult>`.
  - `ModelMap` registers a custom type once (`models.Map<Widget, MyWidget>()`) so every `Widget` the client reads — as a response, a nested property, or a list item — is created as `MyWidget`. It lives in the serializer of the exposed `IFlurlClient`, so raw Flurl calls get it too.
  - Collection request bodies are accepted as covariant `IEnumerable<T>` / `IReadOnlyDictionary<string, T>`, and merge-patch bodies as covariant `IMergePatch<T>`, so a `List<MyWidget>` or `MergePatch<MyWidget>` can be sent where the declared model is expected.
  - Custom subtypes of `@discriminator` models are sent with their discriminator and can be read directly by generic overload or through the model map.
  - A non-success response throws Flurl's `FlurlHttpException`; whether an API accepts extension properties is left to the API and the implementor.
- Enums are read and written as their declared wire values through a converter generated for each enum, instead of `JsonStringEnumConverter`, which ignores `[EnumMember]` and would write the C# member name. Unknown values and non-string tokens are rejected with a `JsonException`.
- `@clientName` rejects anything that is not a plain C# identifier (`invalid-client-name`), so a name cannot produce invalid C# or write outside the `Models` folder.
- A synthesized request record (for example `WidgetCreateRequest`) now reserves its output name like a model does, so a model with the same name is reported as `output-name-collision` instead of being silently overwritten.
- An internal endpoint is an internal property of the aggregate client, and the aggregate client's constructor is internal whenever any endpoint is, so an `@access(Access.internal)` interface no longer breaks the generated project with `CS0053`/`CS0051`.
- The `internal-access-leak` rule now also checks operations marked `@access(Access.internal)`, which are still public in the generated interface, and its advice points at the interface or model that needs to change.
- Numeric enum values are preserved: a member declared with a number is read and written as a JSON number, and an enum can mix string and number members. A value that is not declared, or a token of the wrong kind, throws a `JsonException`.
- Names that come from the TypeSpec are validated (`invalid-name`): a model, enum or interface name must be a valid C# type name, a property, operation or parameter name a valid C# identifier, and a version value must be safe as a folder name. A backtick-quoted name such as `../Evil` can no longer write outside the output directory. Enum member names are sanitized instead (their wire value is kept), and two members that collide are reported. A parameter now honours `@clientName`.
- Unions and literal types map to what is on the wire. `T | null` is `T?`, a union of strings is `string`, and any other union (models, or mixed scalars) is `JsonElement`; previously every union was `string`, which fails at runtime for anything that is not a JSON string. A literal maps to its underlying type instead of `object`. Optional nullable properties and parameters no longer get a doubled `?`.
- `@format("uuid")` / `@format("uri")` / `@format("url")` are honoured on a string property or parameter, not only on a scalar (`Guid` and `Uri`).
- Name collisions are reported instead of emitted as uncompilable C#. Properties (`foo` and `Foo`, a property named after its own record, `EqualityContract` and the other members every record has), operations (`read` and `Read` both become `ReadAsync`), and parameters (`foo` and `Foo`, and the names the generated method already uses) are checked in a per-scope member scope (`name-collision`). Models, enums, interfaces and the generated endpoint, aggregate-client and converter types reserve their names in their shared C# namespace, and so do version namespaces, so a clash is reported as `output-name-collision`.
- Models and enums are collected by qualified name, so two with the same simple name in different child namespaces are both seen and their clash is reported instead of one silently replacing the other. Operations are grouped by the interface or namespace they are declared in rather than by its simple name, so two interfaces called `Items` in different namespaces are no longer merged into one client.
- `internal-access-leak` also checks operations declared directly in a namespace and a public discriminated subtype of an internal base type.
- Wire formats that were silently wrong are now correct or reported. A `@query` array that is not exploded (TypeSpec's default) is sent as `tags=a,b` instead of repeated. A `@cookie` parameter is sent as a cookie instead of being dropped. A duration is ISO 8601 (`PT1H30M`) instead of `01:30:00`. `@encode("string")` on a number is honoured, and an `integer` is a `long`. An unsupported `@encode` is a warning (`unsupported-encoding`).
- A multipart or file body is reported as an error (`unsupported-feature`) and that operation is left out, instead of being sent as JSON. A model that is both a variant and the root of a second discriminator is reported (`unsupported-nested-discriminator`), because `System.Text.Json` mis-reads and cannot write it.
- Models that only an error response uses are generated, so a failed call's body can be read as a typed model.
- Endpoint implementation classes are named `...Endpoint` instead of `...Client`, so an operation declared directly in the service namespace no longer collides with the aggregate client by default.
- A merge patch serializes values with the same options as the client, so its wire format matches a body's.
- The package ships only the emitter (`files` whitelist), generated line endings are always LF, and generated public members always carry XML documentation.
- `runDotnetFormat` takes its process runner and filesystem check as parameters so its failure paths are tested, and a failure with an empty stderr now reports the exit code instead of an empty message.
- `project-name`, `client-name` and `root-namespace` are validated before emission (`invalid-option`): a project name such as `../../Outside` would write outside the output directory and a client name such as `class` would generate invalid C#. `@clientName` also rejects C# keywords on models, enums and interfaces.
- Endpoint, client and aggregate-client files reserve their output names across all services, so two services declaring the same interface, or two interfaces given the same `@clientName`, report `output-name-collision` instead of one silently overwriting the other.
- A synthesized request record takes the access of the model it was built from, so a request record for an internal model can reference internal types.
- API versions are projected onto everything that is emitted: operations, parameters, model properties, enum members, `@discriminator` subtypes, and whole models and enums that exist only in some versions. With `all-versions` each version is emitted on its own, into its own folder and `V<version>` namespace with its own models, enums and request records, so a version's types have exactly that version's shape and several versions can be used together.
- `internal-access-leak` now looks through the type arguments of template instances (`Page<Secret>`), and no longer reports the generic instance's own properties, which are not where the leak is.
- The workflow's default token permission is read-only.
- The DI registration captures its model map instead of registering `ModelMap` in the container by type. `ModelMap` is one type shared by every API version, so registering a second version would otherwise have replaced the first version's map.
- Every required reference-type property gets an initializer (`default!`, `[]` or `new()`), so generated models no longer raise `CS8618`.
- NuGet metadata and other option-derived values in the `.csproj` are XML-escaped, wire names written as C# string literals are escaped, and version values such as `sprint-42` produce a valid namespace segment (`Vsprint_42`).
- Raw request and response bodies: a `bytes` body or response, and a `string` body or response with a non-JSON media type, are sent and read raw instead of being JSON-encoded.
- Path values are fully percent-encoded; query, header and path values use enum wire names, lower-case booleans, and ISO 8601 dates.
- A parameter named after a C# keyword is escaped (`@params`), and a `Content-Type` header parameter is no longer exposed, because the body's media type decides it.
- `example/custom-models`, plus an MSTest end-to-end suite (`e2e/CustomModels.Tests`) that runs the generated C# against a stubbed HTTP layer to verify derived models round-trip.
